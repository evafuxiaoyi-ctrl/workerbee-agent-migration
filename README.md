# WorkerBee 智能体迁移 Skill：第一次使用

这个文件包是给 Codex 使用的操作说明，不是 WorkerBee 程序，也不会自行执行迁移。无需先填完所有技术信息，使用时 Codex 会一次问你一个问题。

## 安装

1. 下载并解压 `workerbee-agent-migration.zip`。
2. 找到 `workerbee-agent-migration` 文件夹，打开后应直接看到 `SKILL.md` 和 `references`。不要只复制 `SKILL.md`，也不要把外面多套的一层文件夹当作 Skill。
3. 在能访问这份文件的 Codex 中，告诉它解压文件夹的位置，再发送下面这段话：

> 请把这个 workerbee-agent-migration 文件夹安装为我的 Codex Skill。先确认当前 Codex 的技能目录；将完整文件夹复制到该目录，不要修改其他设置。如果已存在同名 Skill，先告诉我，不要覆盖。完成后检查是否能识别它。只安装 Skill，不安装 WorkerBee，不登录平台，不执行迁移。

Codex 的技能安装目录通常是 `$CODEX_HOME/skills`；没有设置 CODEX_HOME 时通常为 `~/.codex/skills`。你不需要自己在终端填写这些变量，让 Codex 检查当前环境即可。如果 Codex 看不到你下载的文件，先把文件放到它可以访问的项目目录，或按当前客户端支持的方式提供文件，然后重新告诉它位置。

## 开始使用

安装确认后，在下一条消息输入：

> 请用 $workerbee-agent-migration 帮我把 WorkerBee 的智能体迁移到另一个工作区。我是新手，请一次只问我一个需要补充的问题；能检查到的信息就帮我检查。保留源工作区，不覆盖目标已有内容。

你可以直接回答工作区和智能体的名字，不需要预先找 ID。问到“在哪台电脑或服务器运行”时，不清楚就答“请先检查并推荐”；问到测试任务时，可以答“请帮我拟一条”。不要把密码、密钥或令牌贴进聊天。

如果 Codex 无法识别 Skill，先让它检查解压层级、完整文件和实际技能目录，而不是重复安装或覆盖。安装后仍无法发现时，可在新对话再试，并向 Codex 提供具体报错。

## 会发生什么

Codex 先检查 CLI、权限和依赖，说明迁移方案，再在已授权范围内继续。需要新授权或你决定的问题才停下来问。CLI 尚未安装、没有目标权限或存在同名冲突，都可能需要先处理；Skill 不会绕过这些限制。

迁移结束时，Codex 会单独告诉你 B 里谁能运行、谁能查看配置。如果要你手动配置，它会在结果开头标出这一步，并给出已核实的入口。仅让同事运行时，不需要因此打开「允许他人查看配置」。

“配置已建”不代表已经可运行。最终报告会分别说明迁移了什么、哪些测试实际通过、哪些仍需你操作。它不会自动删除源智能体、切换生产流量或打开定时任务。

本包经过结构校验和模拟场景检查，没有在真实 WorkerBee 环境完成端到端迁移测试。
