# 执行时核对清单

## 能力证据

WorkerBee 产品名也可能被写作 Worker B。以用户提供的服务地址、已有 CLI 及官方文档确定具体部署，不凭名称安装软件。

以下是特定公司部署的文档入口，只作为定位线索。先核实用户使用的实例确实属于该部署，才使用这些入口；其他部署请查其对应官方文档，不能将用户资料发往以下域名。执行时验证访问与版本：
- https://workerbee.51talk.biz/docs/cli
- https://workerbee.51talk.biz/docs/ai-guide
- https://workerbee.51talk.biz/docs/install-agent-runtime

如果这些入口不可访问，优先读取已安装 CLI 的帮助及用户授权的本地文档，不将失效链接或上游文档当作能力证明。不要抓取整个用户目录，也不要输出凭据配置文件内容。

上游参考仅帮助理解对象边界，不证明 WorkerBee 支持相同命令：
- https://multica.ai/docs/workspaces
- https://multica.ai/docs/skills
- https://multica.ai/docs/agents-create
- https://multica.ai/docs/cli

为每个即将执行的写入建立证据：当前版本支持的操作和参数、显式目标工作区、输入对象、预期输出以及只读回查方法。没有证据就不执行。无法显式指定工作区时，避免并发切换全局上下文，写入前再次核实当前目标；任何上下文更改也必须符合授权。

## 脱敏迁移记录

在用户授权的本地工作目录记录即可，无需上传：

| 项目 | 记录内容 |
| --- | --- |
| 任务范围 | A/B 稳定 ID、智能体 ID 集合、目标运行环境、用户授权范围 |
| 能力证据 | CLI 版本、官方帮助/文档依据、实际支持的迁移方式 |
| 对象映射 | 类型、源 ID、目标 ID、状态；依赖先于智能体 |
| 配置差异 | 指令、模型、参数、文件完整性、知识与访问边界 |
| 凭据 | 仅名称/用途/是否需重新授权，绝不记录值 |
| 进度 | 计划、已创建、已回读、已验收、失败或待用户步骤 |
| 验收 | 实际执行的检查、结果与未验证项；不得伪造测试 |

只记录需要的数据。源指令或知识可能含私人内容，默认不全文复制进报告。文件完整性可比较相对路径、数量和摘要，不能仅靠同名判断一致。若平台不提供导出或完整回读能力，清楚记录验证限制。

## 常见边界

- “把智能体迁到 B”不意味着删除 A，也不自动包含全部历史、任务和外部连接。
- A/B 成员不同会改变资料接收范围；不清楚时确认具体数据与 B 的受众。
- 修改运行机器上的模型/环境配置可能影响其他智能体，先判定共享范围，不能作为局部复制顺带修改。
- dry-run 参数是否存在必须查证；自己将一条写入命令称为“预演”不能使它变成只读。
- 测试工具连接时优先只读探测。模型调用即使不写外部数据也可能计费。
- 若当前用户只要 Skill 或模板，交付文件即可，不登录平台或执行迁移。
